## 2. 这个环境的坑（能省你半小时）

- **沙箱写入授权**：受限进程**写不进 `.git`**、也删不了已存在目录里的文件 → 「提交 / 推送 / 删文件」需要一次 `danger-full-access` 批准（用 `sandbox_permissions` + 中文理由）。改文件用 `write`/`edit` 工具即可，不需要批准。
- 宿主其实是 **Windows PowerShell 5.1**（`pwsh` 不在 PATH）；要起子进程用 `powershell -NoProfile -File`。
- `node --test "tests/**/*.test.ts"` → **spawn EPERM**（沙箱禁子进程管道），所以**逐个测试文件跑**。
- `node scripts/smoke.mjs` **能跑**（它 spawn 用 `stdio:'ignore'`）；`scripts/render-check.mjs` **跑不了**（Vite 要 spawn esbuild）→ 这条只能让用户在正常终端跑。
- 推送 GitHub：**用默认 schannel**，别加 `-c http.sslBackend=openssl`（这台机器上 CA bundle 路径不存在）。
- 仓库根有 **28 MB 的 `.tmp-session-dump/`**（会话转录垃圾）：**别提交**，等用户处置。

## 4. 决策索引（全文在 `specs/007-decisions.md`）

- **ADR-013** 只读真相**只给 NPC 自己视角**，绝不注入玩家背包（交付与否由代码核对）
- **ADR-014** 有守恒的不设数值上限（道具奖励无上限，背包即天花板）；没有守恒的才设（好感度）
- **ADR-015** 关系阶段（萍水/相识/知交/知己/莫逆）取代数值门闩：影响**态度**，不拦内容
- **ADR-016** 主观估值（她在意的 ×3 / 她多余的 ×0.5）**只进叙事**，绝不作为驳回依据
- **NFR-013** 叙事与裁决的边界：唯一能做硬判定的，只有守恒类约束（库存 / 预留 / 幂等 / 目标原语白名单）
- 需求：`FR-015`（32 件道具 + uses 词表）、`FR-017`（奖励，已按 ADR-014 改）、`FR-022`~`FR-025`

## 5. 改代码前必读的硬约束

1. **裁决层四条纪律**：幂等（`requestId`）/ 原子（拒绝＝世界逐字节不变）/ 预留锁 / 守恒。
2. **服务端只做形状归一化**，规则只在 `src/lib/quest/`（NFR-011）——别把白名单搬到服务端。
3. **提示词里绝不能出现玩家背包**（ADR-013）。
4. **`desk` 模式必须与改造前逐字节一致**（请求体、提示词、抽取通道、候选卡）。
5. 领域层是纯函数、可 `node --test` 直接跑；React 胶水要尽量薄。

## 6. 省钱纪律（写给下一个我）

- **不要用 `subagent_fork`** —— 它继承全部历史，每发一条消息就重发一遍全量上下文。要派活用全新 `subagent` + 自包含简报，或自己干。
- 别整文件重读，用 `grep` + `read` 的 `offset/limit` 定位。
- 汇报压短：**结论 / 风险 / 下一步**，细节等对方点名再展开。
- 用户在意 token：动手前先想清楚要改哪几个文件，别边试边读。
