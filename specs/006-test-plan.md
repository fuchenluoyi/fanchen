# 006 测试与验收计划

## 1. 测试策略

```
        ┌──────────────┐
        │ 手工验收 M-* │  浏览器里按 002 的 AC 逐条走
        ├──────────────┤
        │ 冒烟 S-*     │  scripts/smoke.mjs：无 UI 的接口链路自检
        ├──────────────┤
        │ 单元 U-*     │  node --test：纯函数 + 解析器 + 路径安全
        └──────────────┘
```

原则：
- **能单元测的绝不靠手点**：规则引擎、相似度、去重、JSON 容错、路径穿越防护全部有自动化用例。
- 需要真实模型的场景（流式、tool_calls）用手工验收 + 可选的 `AI_API_KEY` 环境变量跑冒烟。
- 无凭据也必须能跑通冒烟（验证降级路径）。

## 2. 单元测试用例（`pnpm test`）

### U-01 规则引擎：强需求句命中
输入 `"我需要一个能给团队用的值班排班工具"` → `hit=true`，`reasons` 含 `需要`。

### U-02 规则引擎：闲聊不命中
输入 `"今天天气不错"` / `"哈哈哈"` → `hit=false`。

### U-03 规则引擎：多需求切分
输入含列表：
```
我觉得需要这几样：
1. 支持换班申请
2. 自动提醒
3. 导出 Excel
```
→ 至少产出 2 个候选，且标题非空。

### U-04 相似度与去重
- `similarity("支持换班申请","换班申请功能")` ≥ 阈值。
- `isDuplicate(候选, 既有任务列表)` 对高相似返回 `true`，对不相关返回 `false`。

### U-05 工具调用参数校验
合法 `{title, detail}` 通过；缺 `title` / `title` 为空串 / 类型错误 → 拒绝，且给出原因。

### U-06 抽取编排降级
- `extractMode='off'` → 候选为空，且不调用网络（注入了假 fetch，断言未被调用）。
- 无 `apiKey`、文本为需求句 → 返回 `origin='rule'` 的候选。
- `fetch` 抛异常 → 回退规则候选而非抛出。

### U-07 JSON 容错解析
覆盖：裸 JSON、```json 围栏、前后有解释文字的 JSON、`{"tasks":[]}`、完全非法文本（返回 `null`）。

### U-08 路径穿越防护
`/../server/index.mjs`、`/..%2f..%2fpackage.json`、`/static/../../etc/passwd` → 均被拒绝（非 200）。

## 3. 冒烟测试（`node scripts/smoke.mjs [baseUrl]`）

| 步骤 | 断言 |
| --- | --- |
| S-01 | `GET /api/health` → 200，`ok=true`，含 `defaults` |
| S-02 | `POST /api/chat` 空凭据 → 400 `missing_credentials` |
| S-03 | `POST /api/chat` `baseUrl="ftp://x"` → 400 `invalid_base_url` |
| S-04 | `POST /api/chat` 空 `messages` → 400 `invalid_messages` |
| S-05 | `POST /api/extract` 空凭据 → 400 `missing_credentials` |
| S-06 | 超大 body（2 MB）→ 413 |
| S-07 | 路径穿越 URL → 非 200 |
| S-08 | 若存在 `AI_API_KEY`：`POST /api/extract` 真实调用 → 200 且 `tasks` 为数组 |
| S-09 | 若存在 `AI_API_KEY`：`POST /api/chat` 流式 → 至少收到 1 个 `delta` 与最终 `done` |

S-01..S-07 无需凭据，CI/本地必跑；S-08/S-09 有凭据时启用。
