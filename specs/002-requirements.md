# 002 需求规格（含验收标准）

约定：`FR` = 功能需求，`NFR` = 非功能需求。
每条需求必须给出**可判定的验收标准（AC）**，验收时逐条勾选。

---

## 功能需求

### FR-001 对话区
系统 SHALL 提供与 AI 的多轮对话界面。

- AC-1.1 消息按时间顺序显示，区分 `user` / `assistant` 角色。
- AC-1.2 助手回复**逐字流式**渲染（首字延迟 < 3s 量级，取决于模型）。
- AC-1.3 `Enter` 发送、`Shift+Enter` 换行；空白输入不可发送。
- AC-1.4 生成中对话区自动滚动到底部；用户手动上滚时不强制拉回。
- AC-1.5 输入框在生成期间可继续输入，但发送被禁用（或走"中断并发送"）。

### FR-002 模型接入配置
系统 SHALL 允许用户在页面内配置 OpenAI 兼容服务。

- AC-2.1 可配置字段：`baseUrl`、`apiKey`、`model`、`temperature`、`systemPrompt`、`stream`、`enableTools`。
- AC-2.2 配置保存在 localStorage，刷新后仍在。
- AC-2.3 `apiKey` 以密码框呈现，默认不回显明文；提供"显示"开关。
- AC-2.4 若服务端设置了环境变量 `AI_BASE_URL` / `AI_API_KEY` / `AI_MODEL`，前端未填时自动使用并给出提示。
- AC-2.5 `baseUrl` 末尾斜杠自动归一化，不产生 `//chat/completions`。

### FR-003 连接自检
系统 SHALL 提供连通性自检。

- AC-3.1 顶部状态栏显示后端健康状态（`/api/health`）。
- AC-3.2 设置面板提供"拉取模型列表"（`/api/models`），成功时以下拉框供选择。
- AC-3.3 设置面板提供"测试对话"，发送一条极短消息并显示回显/错误。

### FR-004 工具通道（Agent 主动登记任务）
系统 SHALL 向模型暴露 `create_task` 工具，并在模型调用时把任务推给前端。

- AC-4.1 请求体携带 `tools: [create_task]`（当 `enableTools` 为真）。
- AC-4.2 服务端正确**拼装流式分片**的 `tool_calls`（按 `index` 聚合 `arguments` 片段）。
- AC-4.3 前端收到 `tool_call` 事件后，任务进入"候选卡"或直接入列（取决于 `autoAccept`）。
- AC-4.4 参数不合法（缺 `title`/`detail`）时被拒绝并记录审计信息，不产生脏任务。
- AC-4.5 若模型返回 400 且明确与 tools 相关，服务端自动**去掉 tools 重试一次**，并告知前端"该模型不支持工具调用"。

### FR-005 抽取通道（规则触发 + LLM 精抽）
系统 SHALL 在每轮助手回复结束后运行需求抽取。

- AC-5.1 先跑**规则引擎**；未命中则不调用 LLM（省成本）。
- AC-5.2 命中且具备凭据时，调用服务端 `/api/extract` 做结构化抽取，返回符合 `Task` 结构的结果。
- AC-5.3 LLM 返回非法 JSON 时，服务端做容错解析（去 ``` 围栏、截取首个合法 JSON 对象）。
- AC-5.4 LLM 抽取为空但规则命中时，回退使用规则候选。
- AC-5.5 `extractMode = off` 时完全跳过抽取通道。

### FR-006 无凭据降级
系统 SHALL 在没有可用凭据时仍能产出任务。

- AC-6.1 未配置 `apiKey` 且服务端无 `AI_API_KEY` 时，抽取通道仅使用规则引擎。
- AC-6.2 该类任务的 `origin` 标记为 `rule`，UI 上有可见标识。
- AC-6.3 不因缺少凭据抛出未捕获异常或阻塞对话。

### FR-007 任务卡确认入列
系统 SHALL 以"接任务"的方式让用户确认候选。

- AC-7.1 候选以卡片形式出现在任务面板顶部，显示标题、详情、优先级、来源（原话片段）、`origin`、置信度。
- AC-7.2 每张卡有"采纳"与"忽略"操作。
- AC-7.3 设置中开启 `autoAccept` 后，候选自动入列并给出轻提示。
- AC-7.4 采纳后卡片消失，任务出现在清单列表中。

### FR-008 任务清单管理
系统 SHALL 支持任务的完整生命周期管理。

- AC-8.1 字段：标题、详情、分类（feature/bug/content/question/other）、优先级（P0/P1/P2）、验收要点数组、状态、来源、创建/更新时间。
- AC-8.2 状态流转：`pending 待办 → active 进行中 → done 完成`，任意状态可 `dropped 废弃`。
- AC-8.3 提供状态筛选（全部/待办/进行中/完成/废弃）与计数。
- AC-8.4 可删除任务（二次确认）。
- AC-8.5 可按优先级排序展示。

### FR-009 去重与合并
系统 SHALL 避免同一需求反复入列。

- AC-9.1 候选入库前与既有任务做相似度比较，低于阈值直接丢弃。
- AC-9.2 相似度用字符三元组 Jaccard 计算（纯函数、可单测）。
- AC-9.3 同一轮回复内产生的多个候选之间也去重。
- AC-9.4 被丢弃的候选记录到审计日志（可查看原因）。

### FR-010 持久化
- AC-10.1 设置、消息、任务分别持久化到 localStorage（带版本号 key）。
- AC-10.2 版本不匹配或数据损坏时回退为默认值，不白屏。
- AC-10.3 提供"清空对话""清空任务""重置全部"三个操作，均需二次确认。

### FR-011 会话管理
- AC-11.1 "新建会话"清空消息但**保留**任务。
- AC-11.2 发送给模型的上下文只取最近 N 轮（默认 20 条），可配置。

### FR-012 错误呈现
- AC-12.1 网络失败、401/403、429、5xx 分别给出可读中文提示。
- AC-12.2 错误消息以特殊样式出现在对话流中，不打断后续对话。
- AC-12.3 服务端不把 apiKey 写入日志或错误响应。

### FR-013 停止生成
- AC-13.1 生成中显示"停止"按钮，点击后通过 `AbortController` 中断请求。
- AC-13.2 已生成的部分内容保留，并标记为"已中断"。

### FR-014 抽取审计
- AC-14.1 每条任务记录 `origin`（`llm` / `rule`）、`confidence`、`sourceMessageId`、`triggerReasons`。
- AC-14.2 UI 可查看某任务的来源消息（点击"查看原话"高亮对应消息）。
- AC-14.3 面板底部展示一次抽取的简要结论（是否触发、走了哪条通道、耗时）。

## 非功能需求

### NFR-001 零后端运行时依赖
- AC-1.1 服务端仅使用 Node 内置模块（`node:http`、`node:fs`、`node:path`、全局 `fetch`）。
- AC-1.2 `package.json` 的 `dependencies` 中不含服务端库（express 等）。

### NFR-002 构建产物体积
- AC-2.1 `dist` 中 JS 总计（gzip 前）≤ 600 KB，gzip 后 ≤ 250 KB。
- AC-2.2 构建无警告级别以上的报错。

### NFR-003 类型安全
- AC-3.1 `tsc --noEmit` 零错误，`strict: true`。
- AC-3.2 不使用 `any` 作为公共 API 类型（`unknown` + 收窄）。

### NFR-004 纯函数可测
- AC-4.1 规则引擎、相似度、去重、JSON 容错解析为**无副作用纯函数**。
- AC-4.2 这些模块可被 `node --test` 直接加载（不依赖 React/DOM）。

### NFR-005 可访问性基础
- AC-5.1 对话区 `aria-live="polite"`，任务计数有 `aria-label`。
- AC-5.2 所有交互元素可 Tab 到达，焦点样式可见。
- AC-5.3 颜色对比度 ≥ 4.5:1（正文）。

### NFR-006 安全
- AC-6.1 API Key 只存在于浏览器 localStorage / 服务端进程环境变量，服务端不落盘。
- AC-6.2 静态文件服务拒绝路径穿越（`..`、绝对路径、编码变体）。
- AC-6.3 代理接口只转发到配置的 `baseUrl`，且 `http/https` 之外协议一律拒绝。
- AC-6.4 请求体大小上限 1 MB。

### NFR-007 响应式
- AC-7.1 宽度 ≥ 1024px：左右两栏（对话 + 任务）。
- AC-7.2 宽度 < 900px：上下堆叠，任务面板可折叠。

### NFR-008 单命令启动
- AC-8.1 `pnpm dev` 同时启动前端 5173 与后端 8787。
- AC-8.2 `pnpm build` 产出 `dist`；`pnpm start` 由后端托管 `dist`，单端口可用。
- AC-8.3 **与包管理器解耦**：所有 npm scripts 内部只调用 `node`，不嵌套任何包管理器命令，因此 `npm run <x>` 与 `pnpm <x>` 完全等价（机器上没装 pnpm 时用 npm 即可）。
- AC-8.4 提供 `dev.cmd`：双击即可启动；脚本需以中文 Windows 的**本机编码（GBK/936）+ CRLF** 保存，否则 cmd 会把中文读成乱码并当成命令执行。

# 第二轮：NPC 委托系统

> **语义反转说明**：以上 FR-001~FR-014 描述的是「NPC 问玩家需要什么」；以下需求描述的是
> 「**NPC 自己需要什么，玩家去满足**」。两者是相反的对象，所以新增编号，不改写旧编号。
> 详细设计与校验规则表见 [008-npc-quest-domain.md](./008-npc-quest-domain.md)。

## 功能需求（第二轮）

### FR-015 道具与珍贵等级
系统 SHALL 提供道具白名单注册表，每件道具有珍贵等级与参考价值。

- AC-15.1 珍贵等级五档：凡品 / 良品 / 上品 / 珍品 / 绝品，各带参考价值区间。
- AC-15.2 每件道具的价值必须落在自己那一档的区间内（`auditItemTable()` 自检零问题）。
- AC-15.3 目标与奖励只能引用注册表内的道具 id，未登记一律拒绝（`unknown_item`）。
- AC-15.4 支持按名称与标签检索，供模型在歧义时挑候选。

### FR-016 NPC 背包
系统 SHALL 为每个 NPC 配备背包，且玩家与 NPC 共用同一套背包结构。

- AC-16.1 背包分为「可用」与「已预留」两份；不变式：拥有总量 = 可用 + 已预留。
- AC-16.2 提供增加、扣减（可用）、预留、释放、核销五类**纯函数**操作，入参不被修改。
- AC-16.3 数量不足时操作失败并抛领域错误，背包保持原样。
- AC-16.4 NPC 背包拿不出奖励时，该 NPC 无法发布道具型委托（天然的奖励闸门）。

### FR-017 奖励系统
系统 SHALL 让奖励只来自 NPC 背包内的道具或 NPC 自身的功能。

- AC-17.1 奖励类型白名单：`item` / `affinity` / `ability` / `info` / `none`（放弃奖励）。
- AC-17.2 档位三档：薄礼 / 中酬 / 重谢；道具与好感度各有价值上限，由代码查表裁决。
- AC-17.3 档位上限由「任务重要性 + NPC 慷慨度」决定，**模型自报档位不得超过该上限**。
- AC-17.4 功能解锁（结缘 / 切磋 / 秘传）只允许出现在「大事」上。
- AC-17.5 **发布委托时预留锁定奖励**，防止同一件道具被两个委托同时承诺出去。
- AC-17.6 婉拒 / 撤销 / 过期时释放预留；结算时核销预留并转移给玩家。

### FR-018 目标原语白名单
系统 SHALL 只接受可判定的目标原语，拒绝无法验证的目标。

- AC-18.1 原语集合：`deliver_item` / `has_item` / `talk_count` / `affinity_at_least` / `defeat`。
- AC-18.2 依赖尚不存在系统的原语（`defeat` 依赖战斗系统）拒绝登记（`unsupported_objective`）。
- AC-18.3 `deliver_item` 只能通过提交流程判定，不能靠读一眼背包就算完成。
- AC-18.4 `has_item` 判定不消耗道具。

### FR-019 涌现式 NPC 委托
系统 SHALL 允许委托在运行时现场生成，没有策划模板 ID。

- AC-19.1 委托记录 `provenance`（npcId / sourceDialogueId / draftedBy / createdAt），可追溯来源。
- AC-19.2 状态机：`offered → accepted → settled`，旁路 `declined` / `cancelled` / `expired`。
- AC-19.3 所求者（`requesterId`）恒为 NPC，接取方（`takerId`）恒为玩家。
- AC-19.4 同一 NPC 一次性只挂一个未完结委托（串行任务链）。
- AC-19.5 每次状态流转写入 `history`，每次裁决写入事件流水 `events`。

### FR-020 裁决层
系统 SHALL 由代码裁决委托的合法性；模型只提意图，不直接改世界。

- AC-20.1 每个操作要求 `requestId`；同一 requestId 重放只返回首次结果，世界不再变（幂等）。
- AC-20.2 同一 requestId 换参数复用被拒绝（`idempotency_key_reused`）。
- AC-20.3 任何校验失败都不改变世界（原子性），返回与入参逐字节一致的世界。
- AC-20.4 拒绝以 `{ ok:false, code, message }` 返回，code 覆盖校验规则表全集。
- AC-20.5 道具只在玩家与 NPC 之间转移，世界内道具总量守恒。
- AC-20.6 提供只读快照（`inspectNpc` / `inspectPlayer`）供模型与界面查询事实。

## 非功能需求（第二轮）

### NFR-009 领域层纯函数与零依赖
- AC-9.1 `src/lib/quest/` 不 import React / DOM / localStorage / fetch。
- AC-9.2 世界是可序列化纯数据，可整体克隆（原子性依赖这一点）。
- AC-9.3 全部逻辑可被 `node --test` 直接加载执行，允许使用 enum/namespace 之外的语法限制同 ADR-008。

### NFR-010 领域层可脱离 LLM 验证
- AC-10.1 提供 `pnpm run smoke:quest`（或 `npm run smoke:quest`）：不经 LLM 跑通
  「发布 → 接取 → 校验 → 交付 → 扣除 → 发奖 → 结算」。
- AC-10.2 冒烟脚本覆盖至少 5 条拒绝路径，并断言拒绝后世界不变（`JSON.stringify` 逐字节一致）。
- AC-10.3 冒烟失败必须以非零退出码结束。
